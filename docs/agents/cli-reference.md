# llmtodo CLI reference

Generated by `scripts/gen-agent-docs` from `llmtodo schema`, version 0.1.0. Do not edit by hand.

## Global flags

- `--json`: Print JSON. The default when stdout is not a terminal
- `--human`: Print tables and text for a person
- `--fields`: Keep only these JSON fields, such as `key,title,status.name`
- `--no-input`: Fail instead of asking a question
- `-y, --yes`: Answer yes to confirmations
- `--data-dir`: Data folder. Defaults to LLMTODO_DATA_DIR, then the global config, then ~/Library/Application Support/llmtodo

## Exit codes

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | unknown error |
| 2 | bad flags or arguments |
| 3 | not found |
| 4 | claim held by another session |
| 5 | stale version on a description or document write |
| 6 | validation failed |
| 7 | server unreachable and could not start |
| 8 | input needed, but --no-input is set |
| 9 | this machine is not the primary |
| 10 | patch matched zero times or more than once |
| 11 | forbidden, such as prune by an agent |

## Error codes

Errors print `{"error": {"code": "...", "message": "..."}}` on stderr when the output is JSON.

| Code | Exit code |
|---|---|
| `internal` | 1 |
| `bad_request` | 2 |
| `not_found` | 3 |
| `claim_held` | 4 |
| `stale_version` | 5 |
| `conflict` | 6 |
| `validation` | 6 |
| `unreachable` | 7 |
| `input_needed` | 8 |
| `not_primary` | 9 |
| `patch_mismatch` | 10 |
| `forbidden` | 11 |

## Commands

### `llmtodo init`

Set up llmtodo in this repo: write .llmtodo.toml at the git root and install the agent skill

- `--team <team>`: Team key, such as `ABC`. Asks on a terminal when left out
- `--team-name <team_name>`: Name for a new team. Defaults to the key
- `--project <project>`: Project slug or name. Asks on a terminal when left out. Without a terminal, the file names no project
- `--project-name <project_name>`: Name for a new project. Defaults to the --project value
- `--create` (one of: true, false): Create the team or the project when it does not exist
- `--force` (one of: true, false): Replace an existing .llmtodo.toml
- `--no-skill` (one of: true, false): Do not install the skill in ~/.claude/skills/llmtodo

### `llmtodo skill install`

Install or update the skill in ~/.claude/skills/llmtodo. Keeps files that llmtodo did not write, unless --force

- `--force` (one of: true, false): Back up files that llmtodo did not write, then replace them

### `llmtodo issue query`

List issues that match filters. Sorted by priority, then last update

- `--key <keys>` (repeatable): Only this issue, by key. Repeat for several. Unknown keys are skipped. Skips the default project from `.llmtodo.toml`
- `--team <team>` (repeatable)
- `--project <project>` (repeatable)
- `--all-projects` (one of: true, false): Search every project. Skips the default project from `.llmtodo.toml`
- `--status <status>` (repeatable): Status name. Repeat for several
- `--type <status_type>` (repeatable): Status type: backlog, unstarted, started, completed, canceled
- `--open` (one of: true, false): Only open issues
- `--label <label>` (repeatable): Label the issue must have. Repeat for several
- `--assignee <assignee>`: `me`, `owner`, `none`, or an actor name
- `--parent <parent>`: Parent key, or `none` for top-level issues
- `--milestone <milestone>`
- `--priority <priority>`
- `--for <for_executor>`: Wanted-executor filter, such as `kind=agent,model=opus-5.5`
- `--waiting-on <waiting_on>`: `agent`, `owner` or `none`
- `--depends-on <depends_on>`: Open issues that wait for this issue, directly or through a chain
- `--claimed` (one of: true, false): Only issues an agent has claimed. With `--analyzing`, keeps either
- `--analyzing` (one of: true, false): Only issues an agent is analyzing. With `--claimed`, keeps either
- `-q, --text <text>`: Full-text search over titles, descriptions and comments
- `--similar <similar>`: Duplicate search: issues that look like this text
- `--trashed` (one of: true, false): List the trash
- `--view <view>`: Start from a saved view
- `--description` (one of: true, false): Include descriptions in the output
- `--updated-after <updated_after>`
- `--limit <limit>`: Stop after this many issues. All pages are fetched otherwise
- `--ids` (one of: true, false): Print only the IDs of every match, as one list, in one request

- `-w, --waiting-on <waiting_on>`: `agent`, `owner`, or `none` to clear

- `--worktree <worktree>`: The worktree path for the git panel, or `none` to clear. This machine's host name is stored with it
- `--pr <pr>`: The PR URL for the git panel, or `none` to clear. It is also attached

- `-d, --description <description>`: Replace the whole description. Needs --base-version or --force
- `--description-file <description_file>`
- `--base-version <base_version>`: The description version your text is based on
- `--force` (one of: true, false): Replace the description even if it changed since you read it
- `--section <section>`: Replace the body of one section, chosen by heading or `+++` title
- `--upsert-section <upsert_section>`: Like --section for a `+++` section, but add it at the end when it is missing
- `--body <body>`
- `--body-file <body_file>`
- `--replace <replace>`: Replace one exact string, which must occur exactly once
- `--with <with>`: The new text for --replace
- `--estimate-minutes <estimate_minutes>`: Estimated agent working time in minutes. Changing a set estimate needs --estimate-reason
- `--estimate-cost <estimate_cost>`: Estimated token cost in USD. Changing a set estimate needs --estimate-reason
- `--estimate-reason <estimate_reason>`: The spec change that justifies changing a set estimate

### `llmtodo issue ask`

Ask the owner a question. It goes into the `+++ Owner questions` section, and the issue waits on the owner. Repeat --option for a choice; leave it out for a free-text answer

- `<key>`
- `<question>`: The question, on one line

### `llmtodo issue answer`

Answer an owner question, such as `issue answer LLM-12 Q1 b`. A single option letter picks that option. When no question stays open, the issue waits on agents again

- `<key>`
- `<id>`: `Q1`, or just `1`
- `<answer>`: The answer. An empty string opens the question again

### `llmtodo issue undo-answer`

Take back an answer: the question opens again and the issue waits on the owner. Only the actor who answered can do this. It fails with exit code 6 when another actor wrote to the issue after the answer, the question changed, or the issue is closed

- `<key>`
- `<id>`: `Q1`, or just `1`

### `llmtodo issue review answer`

- `<key>`

- `-m, --feedback <feedback>`: What to change, or a note on the approval

### `llmtodo issue review wait`

- `<key>`: Only answers on this issue
- `--after-seq <after_seq>`: Answers after this activity seq. Pass the `seq` of the last answer you handled, so you miss none between two waits
- `--timeout <timeout>`: Give up after this many seconds, with exit code 1

### `llmtodo api`

Send a raw API request, such as `llmtodo api GET /v1/teams`

- `<method>`: GET, POST, PATCH or DELETE
- `<path>`: Path such as `/v1/teams`
- `--body <body>`: JSON body
- `--body-file <body_file>`

## API routes

|---|---|---|---|

| POST | `/v1/server/backup` | `server backup` | Write a database backup now |

| PATCH | `/v1/teams/{team}` | `team update` | Change a team |

| PATCH | `/v1/statuses/{id}` | `status update` | Change a status |
| DELETE | `/v1/statuses/{id}` | `status delete` | Delete a status that no issue uses |
| GET | `/v1/labels` | `label list` | List labels and label groups |
| POST | `/v1/labels` | `label create` | Create a label or a label group |
| PATCH | `/v1/labels/{label}` | `label update` | Change a label |
| DELETE | `/v1/labels/{label}` | `label delete` | Delete a label and remove it from issues |
| GET | `/v1/projects` | `project list` | List projects |
| POST | `/v1/projects` | `project create` | Create a project |
| GET | `/v1/projects/{project}` | `project view` | Read one project |
| PATCH | `/v1/projects/{project}` | `project update` | Change a project |
| DELETE | `/v1/projects/{project}` | `project delete` | Move a project to the trash |
| POST | `/v1/projects/{project}/repos` | `project link-repo` | Link a GitHub repo to a project |
| DELETE | `/v1/projects/{project}/repos/{owner}/{name}` | `project unlink-repo` | Unlink a GitHub repo |
| GET | `/v1/projects/{project}/milestones` | `milestone list` | List a project's milestones |
| POST | `/v1/projects/{project}/milestones` | `milestone create` | Create a milestone |
| PATCH | `/v1/milestones/{id}` | `milestone update` | Change a milestone |
| DELETE | `/v1/milestones/{id}` | `milestone delete` | Delete a milestone and clear it from issues |
| GET | `/v1/documents` | `doc list` | List documents, optionally for one project (?project=) |
| POST | `/v1/documents` | `doc create` | Create a document |
| GET | `/v1/documents/{doc}` | `doc view` | Read one document with its body |
| PATCH | `/v1/documents/{doc}` | `doc update` | Change a document title or body |
| DELETE | `/v1/documents/{doc}` | `doc delete` | Move a document to the trash |
| GET | `/v1/documents/{doc}/history` | `doc history` | List a document's revisions, with their text only on ?bodies=true |
| POST | `/v1/documents/{doc}/restore` | `doc restore` | Restore a document or one of its revisions |
| POST | `/v1/issues/query` | `issue query` | Query issues |
| POST | `/v1/issues/query/ids` | `issue query --ids` | Query issues for their IDs only, every match in one answer, with no cursor or limit |
| POST | `/v1/issues/frontier` | `issue frontier` | Open, unblocked, unassigned sub-issues of a map issue or project |
| POST | `/v1/issues` | `issue create` | Create an issue |

| PATCH | `/v1/issues/{issue}` | `issue update` | Change an issue |
| DELETE | `/v1/issues/{issue}` | `issue delete` | Move an issue to the trash |
| POST | `/v1/issues/{issue}/restore` | `issue restore` | Take an issue out of the trash, or restore a description revision |
| GET | `/v1/issues/{issue}/history` | `issue history` | Description revisions and activity, with revision text only on ?bodies=true |
| POST | `/v1/issues/{issue}/claim` | `issue claim` | Claim an issue for this session |
| POST | `/v1/issues/{issue}/release` | `issue release` | Release this session's claim |
| GET | `/v1/questions` | `issue questions` | Owner questions, open ones on open issues (?issue=&project=&all=true&cursor=&limit=) |
| POST | `/v1/issues/{issue}/questions/{id}/undo-answer` | `issue undo-answer` | Reopen an answered owner question, unless someone acted on the answer |
| GET | `/v1/issues/{issue}/review` | `issue review show` | The review section and every review answer of an issue |

| POST | `/v1/issues/{issue}/analyze` | `issue analyze` | Mark or unmark this session as analyzing an issue |

| PATCH | `/v1/comments/{id}` | `issue comment update` | Edit a comment |
| DELETE | `/v1/comments/{id}` | `issue comment delete` | Delete a comment |
| GET | `/v1/issues/{issue}/deps` | `issue deps` | The dependency tree of an issue, both directions (?open=true hides closed issues) |
| POST | `/v1/issues/{issue}/relations` | `issue relation add` | Add a relation |
| POST | `/v1/issues/{issue}/relations/remove` | `issue relation remove` | Remove a relation |
| POST | `/v1/issues/{issue}/attachments` | `issue attach` | Attach a link or a local path |
| DELETE | `/v1/attachments/{id}` | `issue detach` | Remove an attachment |

| POST | `/v1/sessions/{session}/notes` | `session note` | Add a note to a session |

| GET | `/v1/activity` | `activity` | Activity events after a sequence number (?after_seq=&issue=&limit=) |
| GET | `/v1/ws` | `activity --follow` | WebSocket of live events. Sends WsMessage values |
| GET | `/v1/views` | `view list` | List saved views |
| POST | `/v1/views` | `view create` | Create a saved view |
| PATCH | `/v1/views/{view}` | `view update` | Change a saved view |
| DELETE | `/v1/views/{view}` | `view delete` | Delete a saved view |

| GET | `/v1/github/status` | `github status` | The last GitHub poll and why it is paused, if it is |

| POST | `/v1/import/linear` | `import linear` | Import or update everything from Linear. Idempotent by Linear ID |
| GET | `/v1/files/{hash}` | `file get` | A stored file, such as an image copied from Linear |
| POST | `/v1/prune` | `prune` | Permanently delete trashed issues or old revisions. Owner only |

Request and response schemas: `llmtodo schema | jq '.api'`.
