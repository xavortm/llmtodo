## Decided (owner, 2026-10-28)

> "Nobody uses the beta yet. Any change may wipe the local cache at this stage, and we start clean. Keep the code simple."

So the app keeps no code that reads a local cache from an older build. This rule covers every path below. It also covers the paths for caches from before [DEMO-21](https://example.com/demo/issue/DEMO-21), [DEMO-26](https://example.com/demo/issue/DEMO-26) and [DEMO-33](https://example.com/demo/issue/DEMO-33). When a change makes old caches unreadable, raise `VERSION` instead of writing a converter. The app does not read a cache of another version. It syncs fresh from the server, as after a sign-out. The next write replaces the old file.

Keep the reader's skip of unknown sections. It costs a few lines, and a removed section can drop out without a version bump.

## Done (PR #109)

* PR: [demo-app#109](https://example.com/demo-app/pull/109), merged as 4c7d2e1 (commit 3b0a9f2).
* `VERSION` is 6. I removed every old-cache path and its tests. `Gated`, `Labels::from_bits`, `tags_of_labels`, `Date::from_text` and `Seed::code` went with them.
* `Cache` holds one field per section. Each section is one `impl Section` block in `cache/sections.rs`. `SECTIONS` in `cache.rs` lists them, and the code sums `MAX_BYTES` from that list. A test checks that `encode` writes exactly the tags of `SECTIONS`, in order.
* `cache.rs` holds the types and the order. `cache/sections.rs` holds the codecs. `cache/file.rs` holds the file, the backup and the writer thread, and `cache/tests.rs` the format tests.
* The mapping between `App` and `Cache` lives in `app/caching.rs`. `NoteRef` replaces each pair of list ID and position.
* The account section keeps only the user ID, and the app syncs the rest from the server.

### Choices made

* `Seed::Sample` **stays.** It is now `#[cfg(test)]`, and so is `ThreeLists`. The list tests, the screen tests and the benchmark scene rely on the sample's known notes. About 125 app tests also edit it through `Setup::with`. No cache holds the sample now. Moving the app tests off it would change their note IDs and gain nothing, so I did not do it.
* The app does not move a cache of another version aside. The file stays in place, and the next write replaces it.
