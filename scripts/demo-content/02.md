## Problem

Demo App needs one end-to-end browser test that stays useful as new features ship. A note that saved on one laptop must never count as synced until the second laptop shows it.

## Rule for this repo

Keep two real laptops and one real server in one run. Use real typing and clicks, real sync timers, visible results and natural pauses of 2 to 6 seconds between steps. Extend this run, and do not split it into many small tests.

+++ Detail: evidence, how to run it, and what is left

Two headed runs passed on 2026-09-06, in 10.6 and 10.2 minutes. Both ran 18 edits with real 8-second sync timers, natural pauses and two laptops. Both ended with the note intact after a reload. The second run also showed a conflict between the two laptops. The runs used no API shortcuts, fast clocks, fake sync, retries or extra users.

The test types known public text: the sample note titles, the tag `home` and the folder name `Inbox`. Any other text fails the test. The sample account still waits for [DEMO-22](https://example.com/demo/issues/DEMO-22). [DEMO-27](https://example.com/demo/issues/DEMO-27) will add fixed test notes in a separate database, so the test never changes a developer's own notes.

Run `scripts/test-e2e-docker.sh` for the same throwaway Linux stack that CI uses. Run `pnpm test:e2e:watch` to watch one run, `test:e2e` for headless, `test:e2e:debug` for the inspector and `test:e2e:report` for the saved files. One run takes 8 to 12 minutes. The test limit is 15 minutes, and the CI job limit is 25 minutes. The test app uses port 5185 by default, and `E2E_BASE_URL` points it at an app that already runs.

A headed `page.screenshot()` call can send a mouse-out event and clear a real hover while it captures. The hover screenshot uses the browser's own capture call, so real pointer behavior does not change. A separate test that keeps the pointer still protects the list view. The final screenshot uses the normal capture.

[DEMO-30](https://example.com/demo/issues/DEMO-30) adds the database history, the cleanup and the reload checks. [DEMO-31](https://example.com/demo/issues/DEMO-31) keeps the wider edge-case runs. A known slow render on the Linux CI stack stays open in [DEMO-33](https://example.com/demo/issues/DEMO-33). A local pass does not mean that bug is fixed. [DEMO-37](https://example.com/demo/issues/DEMO-37) uses this test for separate screenshot checks.

Git ignores the saved files in `app/playwright-report/` and `app/test-results/`, and they stay private, because traces can hold test sign-in tokens. CI keeps the saved files for seven days on throwaway storage. Local test accounts expire as normal. The first pull request, [DEMO-40](https://example.com/demo/pulls/40), merged as `5e6f7a8`. A maintainer agreed to leave the Linux render issue for later.
