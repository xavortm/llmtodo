Part of [DEMO-146](https://example.com/demo/issues/DEMO-146), one way to add a setting, checked by the compiler. This ticket covers target rules 1 and 6. Effort M, low risk. Run the benchmark, because this change touches the frame.

## Today

* `SettingsPage` **exposes its rows.** Callers use `page.toggles` 31 times, `page.inputs` 25 times, `page.pickers` 3 times and `page.dividers` once.
* **Panels add rows in at least five ways**, with 25 `add*` functions: `sync::add(page.inputs, &prefs, …)`, `Account::add(page.inputs, &shown, indent)`, `self.invites.add(page, alpha, &prefs)`, `theme::add_toggles(page.toggles, …)` and `about::add(page, …)`. Each one passes `scale_factor()` by hand.
* `add_section` has two signatures: `(title, icon, index)` in sync, invites, privacy and account, and `(shown, indent, index)` in theme and about.
* Four panels have a `view.rs` (theme, about, shortcuts, export). Four keep their layout in the main file (sync, account, invites, privacy).
* This branch ([DEMO-145](https://example.com/demo/issues/DEMO-145)) adds `RowBatch::count`, `RowBatch::offset_since` and `Panel::offset` for the slide-in animation, which is one more way to add rows.
* **The row budget is a sum kept by hand**, with 33 terms in `settings/draw.rs:76-111`. The onboarding panel is not in it. `RowBatch::push` already drops rows past `MAX_ROWS` and logs once (`ui/rows.rs:476`), as `CLAUDE.md` asks for lists that content fills.
* **Bind slots are bare numbers.** Group 0 has 15 slots, written by hand in `render/scene.rs:840`, `theme.rs:591-640` and `row_cache.rs`. They must agree with `common.wgsl:115-149` and `theme.wgsl:38-42`.
* **The scene uniforms are loose.** `Uniforms` stores flags as 0.0 or 1.0 floats, and `panel_look: [f32; 4]` packs four unrelated values.

## Fix

1. Add a settings pen in `render/page.rs`:

   ```rust
   impl SettingsPage<'_> { pub fn pen(&mut self, scale_factor: f32, prefs: &Prefs) -> Pen<'_>; }
   impl Pen<'_> {
       pub fn section(&mut self, section: &'static Section, group: &Group, offset: Vec2);
       pub fn toggle(&mut self, layer: Layer, toggle: Toggle);
       pub fn picker(&mut self, picker: Picker);
       pub fn divider(&mut self, divider: Divider);
       pub fn panel(&mut self, panel: &Panel) -> Option<PanelId>;
       pub fn alpha(&self) -> f32;
       pub fn prefs(&self) -> &Prefs;
   }
   ```

   The slide-in animation becomes `Pen::offset(offset, |pen| ..)`. The `SettingsPage` fields become private.
2. Every panel gets a `view.rs` with `fn add(&self, pen: &mut Pen)` and one `add_section(title, icon, index)`. This is a plain convention with no trait object. `settings/draw.rs` calls each one in the same way. Its section comes from the `live_section!` macro of sub-task 2.
3. Replace the sum in the row budget with a screen test that fills the busiest page (every panel, 8 accounts, all dialogs and the onboarding panel) and asserts that no row was dropped. Keep the compile-time checks on `MAX_PANELS` and the section batch, which are exact.
4. Add `render/bindings.rs` with named slot constants. Add a test that reads each `@binding(N) var name` from the WGSL and compares it with the table. Writing the constants into the WGSL would be better. Check first whether our naga version accepts a constant inside `@binding`.
5. Pack the uniform flags into one `u32` with named bits, written into the WGSL in the same way as the palette. Split `panel_look` into named fields.

Keep the docs up to date
