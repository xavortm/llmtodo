I audited every dependency manifest on `develop` (5e8f1c2) on 2026-11-07: root tooling, web, admin, docs-site, both Workers, and the Go module. I changed no code.

## Verdict

The dependencies are in good shape. Nothing is urgent.

* **Security:** no known vulnerabilities in anything that ships. The only open alert is one low-severity advisory for a dev-only package (see item 3).
* **Freshness:** every direct dependency is current or a few days behind. The newest releases we lack came out on 4–6 November.
* **Tidiness:** all six lockfiles agree with their manifests, contain no `tarball:` fields, and pass pnpm's supply-chain check. `go mod tidy` and `go mod verify` are clean. Go 1.27.3 is the latest toolchain.
* **Unused packages:** none. The code or a config file uses every listed dependency.

## Suggested follow-ups

These changes are small and can go in one PR, after the current release.

1. **Bump the minor updates.** `vite-plus` and the `vite` catalog alias 1.4.0 → 1.5.0 (root, web, admin), `@playwright/test` 1.65.0, `lucide-react` 1.70.0, `@tanstack/react-query` 5.106.1, `wrangler` 4.158.0, `@cloudflare/workers-types` 5.20261106.1, and `example.com/telemetry-go` v1.39.0 → v1.42.0.
2. **Prune stale** `minimumReleaseAgeExclude` **entries.** 17 of the 19 entries in `admin/pnpm-workspace.yaml` name versions that are no longer in the lockfile. So do 2 of the 3 in `web/pnpm-workspace.yaml`. These entries do nothing. Keep only the ones still in use (admin: `@babel/plugin-transform-typescript@7.29.9`, `get-east-asian-width@1.7.0`, `lru-cache@11.5.3`; web: `scheduler@0.28.0`). Those can likely go too, since all are well past the release-age window.
3. **Decide on the** `deepmerge` **alert.** Dependabot flags `deepmerge` (low, DEMO-ADV-7, no patch exists). It comes from the `shadcn` CLI. Admin keeps that CLI as a devDependency only for `@import "shadcn/tailwind.css"`. It never reaches the browser. The easiest fix is to dismiss the alert as "risk is tolerable". The other choice is to copy that stylesheet into `admin/src` and drop the `shadcn` devDependency. The README already uses `pnpm dlx shadcn@latest` to add components. Dropping it would also remove a large tree of CLI packages from admin installs.
4. **Pin pnpm in docs-site.** `docs-site/package.json` has no `packageManager` field. So it installs with whatever pnpm the machine has (10.28 in the cloud session). Its lockfile also fails `pnpm dedupe --check` on one `vitepress` peer entry. Add `"packageManager": "pnpm@12.0.0"`, run `pnpm dedupe`, and consider adding the docs-site build to `ci:local`. Nothing checks it today.
5. **Silence the root peer warning.** The root project installs `vite-plus` without the `vite` alias that web and admin set in their `pnpm-workspace.yaml`. So `pnpm peers check` reports a missing `vite` peer for `vitest`. This warning is harmless today. The same `catalog` and `overrides` block at the root would clear it.

## Optional, low value

* **d3:** admin imports only `d3-scale`, `d3-shape` and `d3-delaunay` from the full `d3` package. A direct dependency on those three would make installs smaller. The bundle size stays the same, because the bundler drops unused code.
* **howler:** the web sound layer uses `howler` 2.2.4, which has had no release since 2023. It works, so keep it. Look again only if it causes bugs. The Web Audio API would replace it.
* **Automated updates:** the repo has no Dependabot or Renovate config for version updates, so all bumps are manual. A grouped monthly `.github/dependabot.yml` for npm and gomod would keep this audit short next time.
* **One workspace:** the six pnpm projects each have their own lockfile. Web and admin repeat the same catalog and overrides. A single root workspace would remove that repetition. This change is large for little gain, so do it only if the repetition starts to cause problems.

## Held back on purpose

* `@types/node` 26: we run Node 24 (`.nvmrc`), so types 24.x are correct.
* `jsdom` 31: a new major from 5 November, used only in tests. Try it with the next round of bumps.
* pnpm 12.18: the `packageManager` pin stays at 12.0.0. The company package mirror only carries that version (see `docs/learnings/dependencies-build-ci.md`).
* The `semver@6 → 7.7.3` override and the docs-site `vite ^6.4.5` override are both still needed. `eslint-plugin-sonarjs` still asks for semver 6, and vitepress 1.6.4 is still the latest stable.
