## Problem

Testing the sync UI today needs a live account and a running sync server. Timers and state changes move the UI before a developer can check styling, animation, layout on each screen size, or edge cases.

## Rule for this repo

The existing debug bar works only on localhost. UI test screens must stay development-only and use the real sync UI components. They must not create accounts, open a sync socket, send changes, or edit live data.

Each scenario is a fixed fixture that shows one visible sync state. A scenario may run the display behavior needed to inspect that state, such as a countdown. It must not move on to another scenario by itself.

## What to do

* Add a **UI Test** link to the debug bar on localhost.
* Open a separate UI gallery route in the web client.
* Render the real note list and the shared sync UI components with local fixture data.
* Show a fixed left sidebar with the scenarios, numbered in the order a user meets them, from sign-in to sign-out.
* Select the first scenario when the gallery opens.
* Let the developer jump straight to any scenario, without finishing the earlier ones.
* Give every scenario a clear label, not only a number.
* Show clearly which scenario is selected.
* Reset a scenario to its first fixture state each time the developer selects it again.
* Keep the sidebar usable at every supported screen size, without covering the UI under test.
* Add segmented **Desktop / Tablet / Mobile** and **Vertical / Horizontal** controls above the scenario list.
* Resize only the app preview. The debug bar, the screen size controls and the scenario sidebar stay outside the preview at their normal size.
* Put the preview in its own browsing viewport, such as an iframe, so CSS and JavaScript see the selected size. Changing only the width of a parent element is not enough.
* Use these first sizes, and show the active size in the controls:
  * **Desktop:** 1440 × 900 horizontal; 900 × 1440 vertical
  * **Tablet:** 1024 × 768 horizontal; 768 × 1024 vertical
  * **Mobile:** 844 × 390 horizontal; 390 × 844 vertical
* A change of orientation swaps the width and height of the current device. The device type stays the same.
* Start on **Desktop / Horizontal** when the gallery opens.
* Keep the selected scenario when the device or orientation changes. Keep the device and orientation when the scenario changes.
* Render the preview at the exact CSS-pixel size of the preset. If it does not fit, let the work area scroll. Do not shrink the preview or cover it with the sidebar.

### First set of scenarios

Cover at least these visual states, in this order:

 1. Sign-in screen with the first-run message
 2. You pick a name for your first list
 3. Another user picks a name for a shared list
 4. Sync in progress, with a real countdown from 10 to 0, so the warning at 3, 2 and 1 is visible
 5. Sync finished, with the changes from each laptop shown
 6. You add a note to a shared list
 7. Another user adds a note to a shared list
 8. Shared list announcement
 9. You choose who to invite
10. Someone invited you
11. Conflict screen, before you choose a version
12. Conflict screen, with both versions and the chosen one shown
13. Invite outcome, accepted
14. Invite outcome, declined
15. Sign-out summary, all changes synced
16. Sign-out summary, some changes still waiting

When the production component has more than one clearly different result layout, add a separate scenario for each. Do not add controls that turn one scenario into several hidden states.

## Done when

* **UI Test** is visible in the debug bar on localhost and absent on other hosts.
* Opening it shows the first numbered scenario on the note list, with the scenario sidebar visible and **Desktop / Horizontal** selected.
* A developer can select every scenario in the first set directly. Each one renders with sample users, names, colors, note counts, lists, invites and labels.
* Selecting a scenario never signs in to an account. It makes no change through the sync API and opens no sync WebSocket.
* No scenario moves on to the next one by itself.
* The sync countdown runs from 10 to 0 and shows the production warning at 3, 2 and 1. Then it stays on that scenario.
* Selecting a timed or animated scenario again restarts its timer or animation from the beginning.
* A change of device and orientation sets the app preview to the exact CSS-pixel size above, for all six combinations.
* CSS and JavaScript that depend on the screen size see the selected preview size.
* The debug bar, the screen size controls and the scenario sidebar do not resize or scale. They do not appear in screenshots of the app preview.
* A change of device or orientation does not change or restart the selected scenario.
* A developer can select each sign-out summary on its own.
* Normal use and the existing debug bar actions keep working as before.
* Add focused tests for: visibility on localhost, routing, moving between scenarios and resetting them, device and orientation sizes, the separate viewport, state kept while resizing, and no network side effects.
