A debug panel where the owner can change the app's state while testing. It will grow with the app, so a new control must be cheap to add.

## First controls (examples from the owner)

* Add notes to the current list.
* Change the sync delay, the retry count or any other sync number.
* Send fake invites to the inbox.

More controls follow as needed. Possible next ones: turn features on or off, and fill or clear the offline queue.

## Notes

* A key opens and closes it, near F12, which already shows the layout grid. The implementation picks the key.
* It is a dialog built on the existing panels, so it dims the app and takes the input.
* Each control should be one entry in one list, so a new control is one small change.
* Keep it away from normal users, and decide if it ships in release builds.
* We removed the "clear settings on every start" test switch on 2026-10-13. If you need it again, add it here as a control.

## Decided with the owner (grilling, 2026-10-14)

These decisions replace the triage decisions where they differ.

**Builds**

* The panel exists in debug builds only. Release builds have no panel and no key for it.
* After every change, the agent starts the debug build, not the release build. The release build is for the benchmark and final checks. CLAUDE.md says so.
* A debug build shows a Dock icon with a yellow "debug" band across the middle.

**Opening it**

* F10 opens and closes it. Escape also closes it.
* It is a dialog. It dims the app, pauses sync and takes the input.

**Layout**

* One plain panel in the style of the other panels, grouped into Notes, Sync, Invites, Account, Features and App. It scrolls when needed. No effects.
* Each control is one entry in one list.

**Controls**

* Each row is a stepper with − and + buttons. Each entry sets its own step. Shift multiplies the step by 10. Up and down move between rows. Left and right change the value.
* Notes: + only. It adds sample notes to the current list, and the counter in the sidebar counts up.
* Sync, retry and cache: every number in `sync.toml` and `cache.toml`, and the page size. A change is a temporary override. The app drops it on quit or when the file reloads. Each row shows the file's value next to it. A "Print" button writes the changed lines to the terminal as TOML, for the owner to copy into the file. The app never writes the file.
* Invites: send or revoke a fake invite. New invite types join the list as they arrive.
* Features: "Reset all" turns every feature flag back to its default.
* Offline queue: fill and clear. The change lasts until the next sign-in, because the cache does not keep the queue.
* App: "Reset" wipes everything, including the theme, the grid and the stats setting. Then it starts the app as a new user sees it. It asks once inside the panel first. It may restart the app process if that is simpler.

**What stays**

* Notes, invites and flags changed in the panel go into the cache, as in real use.
* The new UI parts are shared widgets for the whole app: steppers, clickable rows, live values in panels and a scrolling list. Only the list of debug controls is debug-only.

**Owner feedback (2026-10-14)**

* Headings get space above and below, with twice as much above.
* All text in the panel is black.
* The icon's "debug" band has square ends and sits a third of the way down, so the logo shows.

**Work**
